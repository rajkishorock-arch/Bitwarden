# VaultGuard System & Security Architecture

## Overview
VaultGuard is a zero-knowledge password management web application. All sensitive vault items (titles, credentials, credit card details, secure notes) are encrypted client-side using standard Web Crypto API algorithms before being transmitted over HTTP or saved to disk.

---

## 1. Zero-Knowledge Cryptographic Foundation
- **Key Derivation (KDF)**: `PBKDF2-HMAC-SHA256` with `600,000` iterations.
- **Domain Separation**:
  - `auth_salt + "_auth_domain"` derives the Account Authentication Hash sent to the server.
  - `vault_salt + "_vault_domain"` derives the Master Encryption Key (MEK) held strictly in memory.
- **Envelope Encryption**: Each vault item is serialized as `{ title, payload }` and encrypted into a single `AES-256-GCM` ciphertext envelope with a 128-bit authentication tag.
- **IV Generation**: A fresh 96-bit (12-byte) random initialization vector (IV) is generated via `crypto.getRandomValues()` for every item creation or update. IV reuse is strictly impossible.

---

## 2. Server Visibility & Plaintext Metadata
The backend FastAPI application and database store encrypted ciphertext blobs and non-sensitive server metadata:

| Field | Visibility | Description |
|---|---|---|
| `id` | Plaintext | Item UUID |
| `user_id` | Plaintext | Owning user UUID |
| `item_type` | Plaintext | Categorization (`login` \| `card` \| `note`) |
| `nonce` | Plaintext | Base64-encoded 96-bit AES-GCM IV |
| `is_favorite` | Plaintext | Favorite status flag |
| `created_at` / `updated_at` | Plaintext | ISO Timestamps |
| `tags` | Plaintext | Tag names and color metadata |
| `encrypted_payload` | Ciphertext | Base64 AES-256-GCM ciphertext containing all titles, usernames, passwords, URLs, card numbers, CVVs, and notes |

---

## 3. Security Tools & Application Features

### A. Cryptographically Secure Password Generator
- Uses `crypto.getRandomValues()` with uniform rejection sampling to eliminate modulo bias.
- Supports length 8 to 64 (default 20).
- Guarantees at least one character from each selected set (uppercase, lowercase, numbers, symbols).
- Evaluates objective entropy ($\text{entropy} = L \log_2 N$) without fake breach score claims.
- Never sends, persists, or logs generated passwords.

### B. Local Vault Health Audit
- Performed 100% locally in browser memory on decrypted items.
- Identifies duplicate/reused passwords, weak passwords (<12 chars or low entropy), missing usernames/URLs, and incomplete card details.
- Never transmits passwords or credentials to remote breach databases or backend servers.

### C. Clipboard Auto-Clear
- Sensitive secrets copied to the clipboard schedule an auto-clear timeout (default 30 seconds).
- Before clearing, the service verifies `navigator.clipboard.readText() === secret` to avoid overwriting user clipboard changes.
- **Limitation Notice**: Guaranteed OS-level clipboard clearing cannot be promised on every operating system or browser environment due to platform permissions.

### D. Auto-Lock Timeout Service
- Monitors user activity (`mousemove`, `keydown`, `touchstart`, `click`, `scroll`) throttled via application timers.
- Resets inactivity timer when unlocked (options: 1m, 5m, 10m default, 30m, Never).
- On expiry, purges MEK reference and clears decrypted items from application state.
- **RAM Disclaimer**: JavaScript garbage collection semantics prevent guaranteed physical RAM zeroization. References are cleared on a best-effort basis.

### E. Password-Protected Encrypted Backup & Restore
- Exports encrypted backup JSON container (`VaultGuardEncryptedBackup` version 1).
- Derives a standalone export key using user-supplied export password and PBKDF2 (600,000 iterations, fresh random salt).
- Encrypts backup contents using AES-256-GCM with a fresh 96-bit IV.
- Import process parses, validates, and decrypts backups locally in RAM before previewing and merging into the vault.
- Plaintext backup files are never generated by default and backup data is never uploaded to the backend server.
